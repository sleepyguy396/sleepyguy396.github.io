Windows Server Infrastructure Labs

A collection of hands-on labs exploring how identity, name resolution, file access, storage controls, web services and address allocation work together in a small Windows environment.

01 / Objective

The repository is a sequence of focused administration labs rather than one fully automated enterprise deployment. The work covers six practical areas: simple file sharing, Active Directory and DNS, NTFS permissions, File Server Resource Manager (FSRM), IIS web-server deployment, and DHCP.

The central question is operational: how can a Windows client discover a service, authenticate to it, and receive only the access or network configuration intended for it? Each lab isolates one part of that workflow so configuration and troubleshooting can be documented separately.

02 / Architecture & service relationships

The diagram below is a conceptual view of the services documented in the repository, not a claim that every role was installed on one production-style server. The lab notes use virtual machines and sanitized documentation IPs for examples.

Identity & DNS

AD DS provides domain identity and group membership; DNS lets clients locate the domain and its services.

File access

SMB share permissions and NTFS permissions both affect effective access. FSRM adds storage quotas and file-screening controls.

Addressing & web

DHCP distributes client network settings. IIS hosts a web service whose availability can be checked independently from domain authentication.

04 / Deep dive: identity and name resolution

The AD DS and DNS lab illustrates a dependency chain that is easy to overlook when troubleshooting: a client needs network connectivity, a correctly configured DNS resolver, records for the domain services, and valid credentials before domain authentication can succeed.

In the documented lab, the domain controller is configured with a static address and points its preferred DNS to itself; the workstation uses the domain controller as its preferred DNS resolver. The notes use qtm.local and RFC 5737 documentation addresses such as 192.0.2.101 and 192.0.2.103 as sanitized examples.

05 / Deep dive: effective file access

File access is not controlled by one permission checkbox. A network user first reaches an SMB share, then Windows evaluates the share permissions and the NTFS permissions on the underlying path. The effective result depends on both layers and the user’s security token.

A good validation plan tests more than “can open folder”: check listing, read, create, modify and delete separately with accounts representing different access groups. For the Guest-only sharing exercise, use only an isolated host-only network; the deliberately weak authentication model is a teaching scenario, not a recommended production configuration.

06 / Validation & evidence

Connectivity & DNS

Capture ipconfig /all, successful nslookup output and the target address used by the test.

Identity & GPO

Show domain membership, test with a standard domain account, and capture applied policy results rather than only the policy editor.

Permissions

Record the test account, attempted action, expected outcome and observed outcome for each ACL case.

Network services

Capture the assigned DHCP lease and a client-side HTTP request to the IIS site, alongside relevant server configuration.

07 / Security considerations & limitations

  • The Guest-only / password-protected-sharing-disabled configuration is intentionally permissive for demonstrating SMB behaviour. Keep it isolated and restore secure settings after the exercise.
  • The lab notes include disabling IPv6 as a troubleshooting/configuration step. Do not treat disabling IPv6 as a universal AD/DNS fix; first diagnose DNS registration, resolver settings and the actual network path.
  • Examples use sanitized documentation IP addresses. They are illustrative and should not be copied as routable production addressing.
  • These are focused learning labs. They do not by themselves demonstrate production high availability, a complete enterprise security baseline, or a fully automated deployment.

08 / What this project demonstrates

This project brings together practical Windows administration skills: role configuration, centralized identity, name resolution, client onboarding, file access control, storage governance, web hosting and automated IP assignment. Its strongest value is the documented troubleshooting path—checking dependencies and validating from the client, rather than relying only on server-side configuration screens.
