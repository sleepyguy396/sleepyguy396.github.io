SECURITY RESEARCH · WEB APPLICATION / PDF PARSING

AI Assignment Marking: security assessment

A source-code audit and isolated validation of a full-stack AI grading application. The assessment confirmed a workflow flaw that can erase stored grading data on re-upload, reproduced a known PyPDF2 cross-reference denial-of-service issue, and documented a separate page-tree recursion defect.

FastAPIPythonPyPDF2Source-code auditIsolated PoC validation
Scope and safety. Testing was performed against source code, scratch files, isolated subprocesses, or a disposable local backend with its own data directory and port. The Gemini call was stubbed where needed. No live production instance or real student data was modified. This write-up describes the evidence in the accompanying assessment; it does not imply that the maintainer has confirmed or fixed every finding.

At a glance

The target is a full-stack assignment-marking application that accepts student PDFs, extracts text, invokes Google Gemini for grading, performs plagiarism similarity checks, and stores submission state in a JSON file. The repository documents a FastAPI backend and React/TypeScript frontend.

Finding 1 — grade destruction through re-upload

Endpoint: POST /api/upload. The upload handler constructs a fresh Submission record with upload-related fields, while grading fields such as score, draft_feedback, and graded_at retain their default None values. The storage layer's upsert() replaces the complete record keyed by student_id, rather than merging upload fields into the existing submission.

Why it matters

  • The tested operation did not require authentication in the isolated app.
  • The prerequisite was knowledge of an existing numeric student ID; the original filename was not required.
  • The demonstrated effect was overwriting one matching record, not changing its student ID. The report did not identify this as an IDOR/BOLA issue.
  • The assessment observed cross-origin requests executing despite a disallowed Origin header and considered CSRF a possible delivery mechanism. Browser exploitability still depends on deployment details such as authentication/session model and browser request constraints.

Severity in supplied report: Medium–High · CWE-841

Root cause and remediation

The problem is a workflow/state-management failure: upload and grading state are stored in the same record, and the upsert is a full replacement. Safer options are to reject re-upload of graded submissions, require an explicit reset confirmation, or merge upload-specific fields while preserving grading state by default. Any operation that clears a grade should be authorized, explicit, and auditable.

Finding 2 — circular PDF /Prev chain

The report reproduced CVE-2026-27628 in the application's installed PyPDF2 3.0.1 code path. The parser follows cross-reference history through a while startxref is not None loop, but the reviewed version does not track visited offsets. A crafted PDF whose trailer's /Prev points back to the same cross-reference section can therefore keep the loop running indefinitely.

The supplied report validated the behaviour in a timeout-bounded subprocess and a disposable application copy, not against the live service. It attributes the issue to CVE-2026-27628 rather than claiming a new CVE. The recommended fix is migration to a maintained pypdf release containing the fix (the report specifies ≥ 6.7.2), alongside parser isolation and hard resource/time limits.

Severity in supplied report: High at application level · CWE-835 / CWE-400 · CVE-2026-27628 is a known issue reproduced in the deprecated PyPDF2 fork.

Finding 3 — page-tree recursion

A separate malformed PDF can make a /Pages node list itself in its /Kids array. PyPDF2's recursive _flatten() traversal then revisits the same node without cycle detection or a depth bound and eventually raises RecursionError.

/Type /Pages
/Kids [2 0 R]   # the node references itself

In the supplied isolated test, the failure occurred after roughly 498 recursive calls in a few milliseconds. The same interpreter and disposable service handled a subsequent valid PDF successfully, so the demonstrated effect differed from the CPU-bound /Prev loop: this one request returned an HTTP 500, but did not keep the backend unavailable.

The report notes that the analogous traversal defect was fixed in maintained pypdf 6.13.2, while PyPDF2 3.0.1 is deprecated and will not receive that fix.

Severity in supplied report: Low · CWE-674.

Validation methodology and boundaries

  • Reviewed the FastAPI upload and storage flow and the installed PDF parser's source.
  • Used scratch JSON storage and synthetic IDs for the grade overwrite test.
  • Used a disposable app instance with its own data directory and port; Gemini was stubbed to avoid production credentials.
  • Ran the PDF parser hang in a timeout-bounded subprocess and checked CPU usage and follow-up service behaviour.
  • Did not test against the live production server or real student data.
  • The report explicitly states that RCE, SSRF, credential exposure, or a new IDOR/BOLA issue were not identified in this validation pass; LLM/prompt-injection testing was not performed.

Recommended remediation priorities

  1. Preserve grading state: make re-upload semantics explicit; prevent silent clearing of score, feedback, and grading timestamps; record state changes in an audit log.
  2. Replace the vulnerable parser path: migrate from deprecated PyPDF2 to a maintained pypdf version containing the relevant fixes.
  3. Isolate PDF parsing: move potentially blocking parsing out of the ASGI event loop into a process/thread boundary with enforceable time and resource limits. A timeout on a coroutine alone does not necessarily stop CPU-bound code running in the same thread.
  4. Harden uploads and browser request handling: apply size and parse-time limits, validate file content, require appropriate authorization and CSRF protections, and avoid trusting the Origin header as the only security control.
